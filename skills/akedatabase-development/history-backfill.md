# 给旧会话的回填提示词

复制下方整段发送给曾参与 AKEDatabase 的会话。

```text
请根据你与我在本会话中实际做过的 AKEDatabase 工作，将对下一位维护者有用的内容直接合入仓库 skills/。本次只授权整理项目文档；按根 AGENTS.md 先读 skills/akedatabase-development/SKILL.md，再读 skills/overview.md 和 skills/memory.md 中与本会话相关的段落。仅核对相关的本地 Git 历史、文件和差异，不执行旧会话遗留的开发、验证或发布任务。

1. 从本会话中找出以后还会影响判断的事实：用户最终确认的决定及理由，已交付的行为和兼容范围，关键表、字段、关联键、公式与适用版本，跨模块依赖，曾造成错误的假设，真正执行过的验证，以及尚待确认的事项和下一步证据入口。记录当时实际完成到哪一步，分别说明代码修改、提交、上传、部署和运行验证。
2. 按版本归档。1.2.0 起，推出新版本号的提交权重最高，核对 appversion 和相关版本差异；保留重要 pre 或修订版的身份及其与正式版的关系。小提交权重居中，只补对接手有用的变化。1.2.0 之前权重最低，只留仍影响现状的设计或兼容背景。没有提交的有效工作可写分支、文件、符号、当时状态；无法定位的记忆注明“会话记录，待核对”。若后来版本已经完成或取代旧方案，请写明新证据。
3. 将本会话的结果、原因、证据、验证范围和余项写入 skills/memory.md 对应条目。跨任务可复用的规则或数据契约合入已有专项 SKILL.md 或其 references，并在 memory.md 留链接；只有项目结构、职责或入口改变时才更新 overview.md。保留有作用域的例外和已确认的用户决定，勿将一次性要求升级为全仓规则。
4. 跳过问候、逐轮对话、命令输出、整份 diff、已被撤回且没有后续影响的想法、重复公告、仅凭猜测的关联，以及其他项目的无关经历。凭据、令牌、私有请求原文和个人信息不要写入仓库。失败只有在能解释现状、避免重犯或揭示尚未完成的工作时才需记录。
5. 写入前重新读取目标段落，按“版本/提交 + 主题”去重，局部合并其他会话已补充的内容。工作树若尚无新版文档，先确认共享仓库位置，不自行创建另一套历史记录。若没有新的有效信息，直接说明已由哪条记录覆盖。不要调整网站版本或提交、推送、发布。

完成后列出改了哪些文档、最重要的一条新增记忆及仍待核实的问题，供我接续。
```
